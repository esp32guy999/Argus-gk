## Acquisition lane: item-level granularity
- **`lidarr_get_album(artist, album)`** — album-level targeting on top of `lidarr_add_artist`.
  Finds/adds the artist (monitor=none, no blanket grab), fuzzy-matches the album, monitors +
  fires a targeted `AlbumSearch`. Fuzzy match is deliberate: "she's so **strange**" still lands
  on "She's So **Unusual**" via token overlap. (`argus/tools/arr_acquire.py`)
- **Fixed the "already in library" dead end** — `*_add_*` used to return "nothing to do" when the
  artist/author/series existed, even if the requested item had **zero files**. Now it fires the
  per-service missing-search command (`ArtistSearch`/`SeriesSearch`/`MoviesSearch`/`AuthorSearch`
  via a new `search_cmd` in SPECS). Caught because Cyndi Lauper was "in the library" but
  *She's So Unusual* had 0/23 tracks.

## Bookshelf repurposed: audiobooks, not ebooks
Owner only cares about audiobooks, so the single Readarr-fork (`bookshelf`, :8787) is now
audiobook-only — **no second instance needed.** The clean realization:
- **`bookshelf:/books` root == `/mnt/user/media/audiobooks` == the Audiobookshelf library**
  (same host path). So anything Bookshelf imports lands straight in Audiobookshelf.
- **qBittorrent `readarr` category had NO save path** → books fell into the `/torrents` root.
  Set it to `/data/torrents/books` (qBt `editCategory`). radarr/sonarr/lidarr were already
  correct (`movies`/`tv`/`music` → `/data/torrents/<type>`).
- **Argus readarr lane now defaults to the `Spoken` profile** (M4B/MP3/FLAC), not `eBook`
  (`qp_prefer`). So `readarr_add_author` grabs audiobooks.

## The Cyberpunk: Edgerunners soundtrack runbook (Lidarr couldn't do it)
A worked example of getting a release Lidarr *won't* import. Reusable when it recurs:
1. **Lidarr album-search found 0** — niche/soundtrack releases (CJK tags, "Vol 1/2/3", "OST")
   don't parse to the MusicBrainz album. Confirmed via `/release?albumId=`.
2. **Metadata profile hides soundtracks** — the "Standard" profile excludes the *Soundtrack*
   secondary type, so the album never shows under the artist. Worked around with a direct
   **`POST /api/v1/album`** by MBID.
3. **All releases were packed `.rar`** the NAS couldn't unpack — `bsdtar` chokes on **UTF-16BE
   CJK filenames** ("Pathname cannot be converted"); no `unrar`/`7z` on Unraid. Route: copy to
   an ASCII name → scp to **anvil** (`7z`) → extract → rsync FLACs back.
4. **The "full OST" was only 4 themes**; the real songs were in the 3 episode volumes — **which
   overlap**. Consolidated + **deduped by title**, parsed real per-track artists out of the
   `title` tag (`"Title" by Artist`; tracks were generically tagged "Cyberpunk"), set a unified
   `Various Artists` album, added cover art (via `mutagen`).
5. Dropped 32 tracks into `/mnt/user/media/music`, **Subsonic `startScan`** → playable in
   Navidrome. Lidarr never tracked it (album 167 deleted afterward); this is a **Navidrome-only**
   delivery, the pragmatic win.

## Gotchas
- **`buzz me` = HA push notification** (owner shorthand) — fire `notify/mobile_app_shanes_iphone`
  via the Argus `/ha/` proxy (`localhost:8210/ha/services/...`), token injected. See memory.
- **`argus-ui` is a systemd `--user` service** — `systemctl --user restart`, never `sudo`
  (system-scope sudo pops a desktop polkit prompt that times out). See memory.
- **qBittorrent**: login returns **204** (not 200); needs a `Referer` header; magnet adds via
  `urls=`, `.torrent` via file upload; `setForceStart` to jump the queue.
- **`/data` namespaces differ per container** on Unraid — qBt `/data`=`downloads/complete`,
  bookshelf `/data`=`downloads/complete` but `/books`=`media/audiobooks`. Always `docker inspect`
  the mounts; don't assume.
