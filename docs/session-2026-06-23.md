# Session 2026-06-23 — OAuth Token Revocation Fix (by claude-box)

## What happened

Claude-box (the CC instance on claude-box VM) was asked to investigate why Argus
kept losing auth to Claude Code after ~30 minutes. 

## Root cause

Three separate credential files (`~/.claude/`, `~/argus/.cchome/`,
`~/.claude-shim-config/`) held different OAuth tokens. When one `claude -p`
subprocess refreshed its token, Anthropic revoked the previous one — which the
other subprocesses were still using. See `docs/postmortem-oauth-token-revocation.md`.

## Changes made (on disk, not yet committed)

1. **`argus/claude_code.py`** — removed isolated `CLAUDE_CONFIG_DIR`. Now uses
   `~/.claude/` directly. `_sync_credentials()` is a no-op. `_clean_env()` pops
   `CLAUDE_CONFIG_DIR` instead of setting it.

2. **`ai-stack/claude-shim/server.py`** (not in this repo) — same pattern: uses
   `~/.claude/` directly, persistent session (peace pattern).

3. **`docs/postmortem-oauth-token-revocation.md`** — full post-mortem with
   timeline, root cause, fix, verification steps, and commit message.

4. **`docs/ISSUES.md`** — added resolved entry with pointer to postmortem.
